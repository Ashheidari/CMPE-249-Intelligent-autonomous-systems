# Implementation Plan: 2D Object Detection — Track A (Experimental)
 
This file is the implementation plan for Claude Code. Work through it **one milestone at a time**. After each milestone:
1. Run that milestone's acceptance checks.
2. Commit with a message like `M3: COCO evaluation pipeline`.
3. Stop and summarize for the user what was done, the key numbers, and anything surprising. Wait for the go-ahead before starting the next milestone.
## Project summary
 
Evaluate three COCO-pretrained detectors from three families, on two datasets, without retraining. Then analyze domain shift and the speed–accuracy tradeoff.
 
| | Choice |
|---|---|
| **Model 1** | Faster R-CNN, two-stage, anchor-based. `torchvision.models.detection.fasterrcnn_resnet50_fpn_v2`, weights `FasterRCNN_ResNet50_FPN_V2_Weights.COCO_V1` |
| **Model 2** | YOLO11s, one-stage, anchor-free. Ultralytics `yolo11s.pt` |
| **Model 3** | Grounding DINO, open-vocabulary, query-based. Hugging Face `IDEA-Research/grounding-dino-tiny` |
| **Dataset 1** | COCO val2017 (5,000 images, 80 classes) |
| **Dataset 2** | KITTI 2D Object Detection, a fixed seeded subset of the labeled *training* split. KITTI test labels are private. |
| **Hardware** | Apple Silicon Mac (M5), PyTorch `mps` backend |
| **Required analyses** | (1) cross-dataset generalization, (2) speed–accuracy tradeoff |
| **Bonus analysis** | (3) closed-set vs. open-vocabulary, using Grounding DINO with KITTI-native prompts |
 
### Global rules
- **One evaluator for everything.** All mAP numbers come from `pycocotools.COCOeval` run by our own script. Never mix in numbers from Ultralytics' built-in `val`, except for the one cross-check in M3.
- **Reproducibility is a deliverable.** Every run writes:
  - its full config (model, checkpoint, input size, thresholds, device, versions) to `results/<run_id>/config.json`
  - its raw predictions to `results/<run_id>/predictions.json`
  - its metrics to `results/<run_id>/metrics.json`
  Every shell command gets appended to `logs/commands.log`.
- **Device selection:** prefer `mps`, then `cuda`, then `cpu`, overridable with `--device`. Set `PYTORCH_ENABLE_MPS_FALLBACK=1` in the run scripts. If an op still fails on MPS, fall back to CPU for that model only, and record that in `config.json`.
- **Determinism:** seed 42 everywhere. Subset selections are saved as file lists and reused, never regenerated.
- **Boxes:** internally always absolute-pixel `xyxy` in *original image* coordinates. Convert to COCO `xywh` only when writing results JSON.
- **mAP thresholds:** for mAP evaluation, use a low score threshold (0.001 for closed-set models) and keep at most 100 detections per image, matching COCO `maxDets=100`. Visualizations use a separate display threshold (default 0.3).
- **Code quality:** keep code small and readable. The user needs to explain it in a report. Prefer plain functions, type hints, and docstrings that say what tensor shapes and box formats are.

## Milestone 0: Environment and data
 
**Tasks**
1. Create a Python 3.11 venv.
2. Install `torch torchvision ultralytics pycocotools "transformers>=4.40" pyyaml pandas matplotlib tqdm pillow`, then pin the exact installed versions into `requirements.txt`.
3. Write `scripts/record_env.py` → `env.txt` with:
   - Python, torch, torchvision, ultralytics, transformers, and pycocotools versions
   - `torch.backends.mps.is_available()`
   - macOS version and chip name (via `sysctl -n machdep.cpu.brand_string`)
   - total RAM
4. Write `scripts/download_coco.sh` to download and unzip val2017 images and the 2017 annotations from `images.cocodataset.org`.
5. **KITTI cannot be auto-downloaded** because it requires registration. Write `scripts/check_kitti.py`, which verifies that `data/kitti/training/image_2/` and `label_2/` exist with 7,481 images and labels each. If they're missing, it prints clear instructions:
   - Register at cvlibs.net
   - Download "left color images of object data set" (`data_object_image_2.zip`, about 12 GB) and "training labels of object data set" (`data_object_label_2.zip`)
   - Unzip both into `data/kitti/`
   Then **stop and ask the user to do this manually.**
6. Initialize git with a `.gitignore` covering `data/`, the venv, and large `results/` files.
**Acceptance:** `env.txt` exists and shows MPS available. COCO has 5,000 images and the annotation JSON loads. `check_kitti.py` passes, or the user has been asked to download KITTI.
 
## Milestone 1: Common detector interface + smoke test
 
**Tasks**
1. Define the interface in `src/models/base.py`:
```python
   class Detector:
       name: str
       def predict(self, image: PIL.Image, class_names: list[str]) -> dict:
           """Returns {'boxes': np.ndarray[N,4] xyxy original-pixel coords,
                       'scores': np.ndarray[N], 'labels': list[str] (class names)}.
           Closed-set models ignore class_names except for filtering."""
```
   Returning class *names* instead of IDs keeps the COCO 80-class problem and the KITTI mapping in one place: the evaluator maps names to dataset category IDs.
2. **Faster R-CNN wrapper:**
   - torchvision weights `COCO_V1`, using `weights.transforms()` for preprocessing
   - set `box_score_thresh` to the eval threshold and `box_detections_per_img=100`
   - map torchvision's 91-index label space to names via `weights.meta["categories"]`
   - document in a comment that torchvision resizes internally (min side 800, max side 1333) and returns boxes in original coordinates
3. **YOLO11s wrapper:**
   - `ultralytics.YOLO("yolo11s.pt")`, `imgsz=640`, `conf` = the eval threshold, `iou=0.7`, `max_det=100`, `device` from config
   - read `result.boxes.xyxy`, which is already in original coordinates
   - map class index to name via `model.names`
4. **Grounding DINO wrapper:**
   - load `AutoProcessor` and `AutoModelForZeroShotObjectDetection` from `IDEA-Research/grounding-dino-tiny`
   - build the text prompt as lowercase class names joined with `" . "` and ending with `" ."`
   - **Prompt length:** the text encoder has a 256-token limit, which 80 COCO class names come close to or exceed. Split the class list into chunks (start with 4 chunks of 20 classes), run one forward pass per chunk, concatenate the detections, then run class-wise NMS (IoU 0.5) per class across chunks. Log the token count per chunk.
   - post-process with `processor.post_process_grounded_object_detection` using `target_sizes=[(H, W)]`. Use low thresholds for mAP (box threshold 0.05, text threshold 0.05; make both configurable), then keep the top 100 by score.
   - **Label matching:** the returned label is a text phrase, not a class ID. Map it to a class name by:
     1. exact match after lowercase and strip
     2. otherwise, the class name that is a substring of the phrase, or the reverse, choosing the longest match
     3. otherwise, drop the detection and count it in a `dropped_unmatched_labels` stat saved in `config.json`
     Document this logic clearly; it goes in the report.
   - Text encoding happens on every call. Keep it in the timed path for the benchmark, and note this.
5. `src/viz.py`: draw boxes with label and score.
6. `scripts/smoke_test.sh`: run all 3 models on the same 5 COCO images. Save visualizations to `results/smoke/`, and print the detection count and per-image time per model.
**Acceptance:** all three models produce sensible boxes on the 5 images (inspect the saved PNGs). Boxes are aligned to the original image, with no resize offset. Note which device each model actually ran on.
 
## Milestone 2: KITTI → COCO conversion
 
**Tasks**
1. Parse KITTI `label_2/*.txt`. Each line has: type, truncated, occluded, alpha, bbox (left, top, right, bottom), dims, location, rotation_y. Only `type`, `truncated`, `occluded`, and `bbox` are needed.
2. Make the label policy configurable in `configs/kitti_mapping.yaml`:
```yaml
   eval_classes: [car, person, truck]     # COCO category names used for KITTI eval
   mapping:
     Car: car
     Pedestrian: person
     Person_sitting: person
     Truck: truck
     Van: ignore            # options: car | ignore   (USER DECISION — default ignore, run both if cheap)
     Cyclist: ignore        # options: person | ignore
     Tram: ignore
     Misc: ignore
     DontCare: ignore
```
   - `ignore` means the box is written as a COCO annotation with `iscrowd=1`, so COCOeval treats it as an ignore region: detections there are neither true positives nor false positives.
   - Add a comment in the code explaining this choice.
3. Select a seeded random subset of 1,500 images from the training split. Save the list to `data/kitti/subset_1500.txt` and commit the list.
4. Write `data/kitti/annotations/kitti_subset_coco.json` using **COCO's own category IDs** for car (3), person (1), and truck (8), so predictions in COCO ID space evaluate directly. Each annotation stores `area = w*h`, plus `truncated` and `occluded` as extra fields for later analysis.
5. Print stats: images, boxes per class, ignore boxes, and the size distribution using COCO's small/medium/large cutoffs of 32² and 96² pixels area.
**Acceptance:**
- The JSON loads with `pycocotools.COCO`.
- 20 random images are rendered with their GT boxes to `results/kitti_gt_check/`, with ignore boxes drawn dashed, and they look right.
- The stats table is saved to `results/kitti_stats.md`.
## Milestone 3: Shared COCO-style evaluation
 
**Tasks**
1. `src/eval/run_inference.py --model {faster_rcnn,yolo11s,gdino} --dataset {coco,kitti} [--limit N]`:
   - iterates images
   - calls `predict`
   - maps label names to the dataset's category IDs
   - for KITTI, keeps only `eval_classes` and drops all other predicted classes
   - writes `predictions.json` in COCO results format (`image_id, category_id, bbox[x,y,w,h], score`) and `config.json`
   - shows a progress bar and supports resuming from partial output
2. `src/eval/coco_eval.py`:
   - runs `COCOeval(iouType="bbox")`, restricted via `params.catIds` to the dataset's evaluated categories
   - saves the 12 standard stats with names: AP, AP50, AP75, APs, APm, APl, AR1, AR10, AR100, ARs, ARm, ARl
   - saves **per-class AP** computed from `eval.eval["precision"]`, averaged over IoU thresholds and recall, ignoring -1 entries
   - saves per-class AP50
   - writes everything to `metrics.json` and pretty-prints it
3. **Sanity check:** run YOLO11s on COCO with our pipeline and with `yolo val` (Ultralytics' own validator) on the same 5,000 images. Report both. They should be close; if not, find out why before continuing (common causes: category ID mapping, box format, `max_det`, letterbox handling).
**Acceptance:** `--limit 200` works end to end for all 3 models on both datasets, and the YOLO cross-check is within about 1 mAP.
 
## Milestone 4: Full runs
 
**Tasks**
1. Run all 6 combinations (3 models × 2 datasets) on the full sets. These are long runs, so run them in the background and log to files.
2. Record in each `config.json`: input resolution, score threshold, NMS/IoU threshold, max detections, device, and wall-clock time.
3. Compare COCO results against approximate published values for these checkpoints:
   - Faster R-CNN R50-FPN v2: about 46.7 AP (torchvision's model card)
   - YOLO11s: about 47.0 AP at 640 (Ultralytics docs)
   - Grounding DINO tiny: high 40s AP zero-shot (paper, Swin-T)
   Flag any result more than about 3 AP away and investigate. Check the actual numbers from the official sources rather than trusting these approximations.
4. `src/analysis/tables.py`: generate `report/tables/main_results.md` and `.csv` (model × dataset × all metrics) and `per_class_kitti.md` (AP for car/person/truck per model on COCO vs. KITTI).
**Acceptance:** 6 complete `metrics.json` files, the main results table, and COCO numbers that are plausible against the published ones.
 
## Milestone 5: Speed and memory benchmark
 
**Tasks**
1. `src/eval/benchmark.py --model X --dataset {coco,kitti}`:
   - batch size 1
   - 20 warm-up images, then 200 timed images, using the same fixed image list for every model
   - time preprocessing, model forward pass, and postprocessing separately, calling `torch.mps.synchronize()` (or the CUDA equivalent) before each timestamp
   - report mean, median, and p90 latency in ms, plus FPS
2. Memory: on MPS, record `torch.mps.current_allocated_memory()` and `torch.mps.driver_allocated_memory()`, with the peak sampled after each image. Note in the output that unified memory makes this not equivalent to CUDA VRAM.
3. Postprocessing should include NMS for Faster R-CNN and YOLO. For Faster R-CNN this happens inside torchvision's forward pass, so state that limitation. Grounding DINO has no NMS within a single prompt, only the chunk-merge NMS on COCO; report its text-encoding share if measurable.
4. Results go to `report/tables/speed.md`.
**Acceptance:** stable timings, with less than 10% difference between two repeated runs of the same model.
 
## Milestone 6: Analysis 1 — cross-dataset generalization
 
**Tasks**
1. For car, person, and truck, compare AP on COCO with AP on KITTI per model. Compute the absolute and relative drop.
2. **Scale analysis:** APs/APm/APl on COCO vs. KITTI, restricted to the 3 shared classes on COCO too (re-run `coco_eval` with `catIds=[1,3,8]` so the comparison is apples to apples).
3. **Occlusion and truncation analysis on KITTI:** recall at IoU 0.5 for car and person, split by KITTI `occluded` level (0, 1, 2) and truncation bucket. Implement this as a small custom matcher (greedy, score-sorted, IoU ≥ 0.5) and document it.
4. **Label-policy sensitivity:** if not too slow, re-evaluate the saved KITTI predictions with `Van: car` instead of `Van: ignore`. This requires only re-evaluation, not re-inference. Report the change in car AP.
5. Figures in `report/figures/`:
   - grouped bar chart of per-class AP, COCO vs. KITTI, per model
   - AP by object size, COCO vs. KITTI
   - recall vs. occlusion level
**Acceptance:** figures and a short `report/analysis_generalization.md` with the numbers and 3–5 bullet observations. Mark interpretations as hypotheses for the user to verify.

## Milestone 8: Bonus analysis 3 — closed-set vs. open-vocabulary
 
**Tasks**
1. Re-run Grounding DINO on the KITTI subset with **KITTI-native prompts**: `"car . van . truck . pedestrian . cyclist ."`.
2. Evaluate two ways:
   - **(a) Mapped:** car+van → car, pedestrian → person, truck → truck, against the same GT as before
   - **(b) Native:** build a second GT JSON where Van and Cyclist are real categories instead of ignore, and evaluate per native class
3. Compare (a) against the COCO-80-prompt run from M4 to show the prompt's effect. Report (b) to show what the closed-set models *cannot* do at all, since COCO has no "cyclist" class.
4. Optional: run 2–3 prompt variants for one class (e.g., "pedestrian" vs. "person" vs. "walking person") and report the AP sensitivity.
**Acceptance:** table plus `report/analysis_open_vocab.md`.
 
## Milestone 9: Failure analysis
 
**Tasks**
1. `src/analysis/failures.py` mines KITTI images per model for:
   - high-confidence false positives (score > 0.5, no GT match at IoU 0.5)
   - missed GT, especially small or occluded objects
   - duplicate detections (two predictions with IoU > 0.5 to the same GT)
   - mapping-induced cases: a prediction on a Van or Cyclist ignore region, or a "bicycle" predicted on a Cyclist
2. Save about 12 example images to `report/figures/failures/`, with GT in green, predictions in red/blue, and a caption. Prefer images where models disagree. Include a side-by-side comparison of all 3 models on 3 of the images.
3. Write `report/failure_cases.md` listing each image, what went wrong, and a one-line hypothesis. The user will refine the explanations.
